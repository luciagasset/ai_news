El cambio de fondo es la arquitectura: el servidor de OpenCode arranca solo como un proceso en segundo plano y todas las interfaces (terminal, web, app de escritorio y scripts propios) hablan con él, lo que facilita tareas programadas o conectarlo con otros equipos. Sus autores reconocen que la API anterior «era mala» y la han rehecho desde cero; el propio agente la usa, por ejemplo, para mover una sesión a otra rama de trabajo de git.

La novedad más técnica es el «modo código»: un intérprete mínimo de JavaScript que convierte servidores MCP y APIs en funciones que el agente combina en un solo script, en lugar de llamarlas una a una, de modo que se pueden añadir «mil» servidores sin saturar el contexto. Llegan también subagentes y comandos en segundo plano, más de 80 plugins internos con recarga en caliente y un SDK para usar OpenCode como librería. The core change is the architecture: the OpenCode server starts on its own as a background process and every interface (terminal, web, desktop app and your own scripts) talks to it, which makes scheduled tasks or connecting it to other machines easier. Its authors admit the previous API “was bad” and have rebuilt it from scratch; the agent itself uses it, for example, to move a session to another git worktree.

The most technical novelty is “code mode”: a minimal JavaScript interpreter that turns MCP servers and APIs into functions the agent combines in a single script, instead of calling them one by one, so that “a thousand” servers can be added without flooding the context. Background subagents and commands also arrive, along with more than 80 internal plugins with hot reload and an SDK for using OpenCode as a library. There are breaking changes: version 1.0 plugins do not work and the server API is different. The announcement drew 886 points and 392 comments on Hacker News.
